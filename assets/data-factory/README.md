# 数据工厂（Data Factory）

> 数据工厂是**抽象造数机制**，不是某个系统的专用工具。
> 它解决的是：测试用例需要前置数据（编辑要商品、发货要订单、审批要工单…），数据从哪来？
> 答案统一为：**由数据工厂基于「项目背景文档」自动生成该系统专属的造数器**。

## 一、是什么（核心概念）

数据工厂 = **一套造数框架 + 一组随项目生成的造数器实例**。

- **框架（不变，所有项目通用）**：前置三态判定、前置构造生命周期、造数结果回填 produced、幂等命名、blocked 归因（数据构造失败/前置缺失）
- **实例（随项目变）**：每个项目根据「项目背景文档」生成专属造数器，如：
  - 电商系统（云商城）→ `createProduct` / `placeOrder` / `createTag`
  - OA 审批系统 → `createRequest` / `createApproval` / `createUser`
  - CRM 系统 → `createCustomer` / `createContract` / `createOpportunity`
  - 工单系统 → `createTicket` / `createAsset`

**换测试对象后数据工厂还有用吗？——有用。** 换系统只是换"造数器实例"（由新项目的背景文档驱动重新生成），框架、生命周期、回填、判定逻辑全部复用。工厂是机制，不是某个系统的商品/订单。

## 二、造数器如何生成（两级信息来源：文档优先 / 探测兜底）

造数器的信息来源**不是必须有背景文档**，而是两级：

### 第一级（首选）：从项目背景文档提取

有「项目背景.md / 环境信息」文档时，提取以下信息生成造数器：

| 背景文档中的内容 | 工厂如何消费 | 产出 |
|------------------|--------------|------|
| 业务实体与数据模型（第 6 章类） | 识别被测系统的核心业务对象（商品/订单/工单/客户…） | 造数器清单（每个实体一个） |
| 造数/变更端点（API 清单） | 找到创建/变更实体的接口（Create/Add/Save…） | 造数器内部 API 调用 |
| 鉴权方式（token 规则/Req-Host/cookie） | 复用鉴权模板 | 统一请求头封装 |
| 测试账号与凭据（附录 B 类） | 注入账号/密码/验证码 | 造数器可执行的前提 |
| 实测数据基线（存量数据/环境说明） | 判断"系统预置"可用性 | 前置三态中"系统预置/环境提供"的兜底 |
| 前端路由/操作链路（造数需走 UI 时） | 提供下单、审批等 UI 造数路径 | UI 型造数器（如 H5 下单支付） |

### 第二级（兜底）：没有背景文档 → AI 自动探测生成背景

**没有背景文档时，靠 AI 自己探测，而不是 blocked。** 探测三通道（与执行三通道同构）：

| 探测通道 | 方法 | 能拿到什么 |
|----------|------|-----------|
| **前端 JS 反编译** | 下载页面 umi/vendor JS，grep 接口路径、控制器、参数 | API 域、端点清单、方法签名（如 LoginController.AliCheckLoginNew 参数名） |
| **网络监听抓包** | Playwright 打开页面，page.on('request'/'response') 监听 | 真实请求体、响应结构、鉴权头要求（Req-Host 缺省 30010 等） |
| **UI 操作录制** | 走一遍业务操作，记录请求 + 页面变化 | 业务流路由、UI 造数路径（下单/审批）、稳定选择器 |

**探测产物 = 背景文档本身**：探测得到的实体/端点/鉴权/账号，整理成「项目背景.md」落盘，之后所有用例/造数器/执行都引用它——**背景文档可以是输入，也可以是 AI 探测的输出**（202608222235-DeepSeek 项目的背景就是实测生成）。

### 硬性规则（"禁止凭空假设"的正确定义）

- **造数必须基于实测事实**：事实来源 = 背景文档 **或** 探测结果（JS 反编译/抓包/录制），两者都算"有依据"
- **唯一禁止的是"拍脑袋"**：没有文档、也不探测，凭空假设系统有某个实体/端点/参数——这不允许
- 两级都用尽仍无法确定造数方式（如系统无开放造数通道）→ 才标记"数据工厂未配置"并 blocked（前置缺失），并说明探测过什么、卡在哪

## 三、目录约定

```
assets/data-factory/
├── README.md               # 本文件（机制说明 + 统一接口规范）
├── auth_template.js        # 鉴权封装模板（从 storage_state 提取 token，Bearer + Req-Host）
└── examples/               # 示例实例（仅供理解，勿直接复用）
    ├── ecommerce/          # 电商示例：create_product / place_order / create_group / create_tag
    │   ├── create_product.js
    │   ├── place_order.js
    │   └── create_tag.js
    └── README.md           # 示例说明：如何从背景文档生成
```

项目实际使用时：复制 examples 结构，按该项目背景文档替换业务实体/端点/鉴权，生成 `runtime/factory/` 下的项目造数器。

## 四、统一工厂接口（所有项目一致）

| 接口 | 作用 | 返回 |
|------|------|------|
| `factory.create<Entity>(params?)` | 创建核心业务对象（商品/工单/客户…） | `{ id, name, ...业务字段, ok, msg }` |
| `factory.place<Flow>(params?)` | 走完一个业务流（下单支付/审批流转…） | `{ orderNo/ticketNo, status, ok, msg }` |
| `factory.apply<Action>(targetId)` | 对对象发起动作（退款/驳回/关闭…） | `{ ok, msg }` |
| `factory.update<Entity>(id, overrides)` | 改字段（字段校验类用例用） | `{ ok, msg }` |
| `factory.get<Entity>(id/条件)` | 只读校验造数结果 | `{ ...业务字段 }` |
| `factory.delete<Entity>(id)` | 用例结束清理，自产自销 | `{ ok, msg }` |

- 所有接口幂等：数据名带时间戳/随机后缀，重复执行不冲突
- 返回统一 `{ ...业务字段, ok, msg }`；`ok=false` → 执行框架标记 `blocked`（blocker_type=数据工厂）
- 造数结果落盘 `runtime/<case_id>_data.json`，并回填 produced（订单号/工单号/客户名出现在实际结果列）

**重要定位（2026-08-25 实测修正）**：
- **数据工厂 = 执行期统一构造层**（可封装 API，也可封装 UI 稳定路径），**不是正式用例步骤**。正式 Excel 只写业务操作，构造动作放在 `data_setup` / setup strategy，由执行器在用例第 1 步之前完成。
- **造数辅助资源按当前项目实际通道准备**：图片、验证码、配送员、基础分类等资源不能默认继承其他项目。当前项目未明确时，先按页面/API/只读探测确认可用通道，再选择复用、上传、创建或环境提供；实际构造失败才标记 blocked。
- **先只读探测，再写参**：参数格式未知时，先用 Get 类只读接口或 UI 抓包摸清系统语义，禁止盲猜（云商城 CreateProduct 的 delivery 是整数数组 `[1,2,3]`、freight 独立顶层字段——盲探对象数组 5 次全 400 的教训）
- **字段校验类用例用 API 双向判定**：`update<Entity>(id, overrides)` 改字段 → 看接口是否接受 → 该拒的拒了 = passed；该拒的没拒 = failed（真校验缺陷）

## 五、与用例/执行框架的关系

```
用例前置三态（case-design.md）
   ├─ 自造 → 正式用例前置写业务状态
   │        → data_setup / setup strategy 调项目造数器 → 注入 → 执行核心步骤 → 回填
   ├─ 系统预置 → 校验背景文档声明的存量数据，缺失 → blocked（前置缺失）
   └─ 环境提供 → 标注来源 + 兜底 blocked
```

- 执行框架只认统一接口，不关心造数器内部是什么系统——所以换项目框架零改动
- 环境门禁"前置构造通道就绪" = 当前项目至少存在一种可用构造路径（API 返回真实 id，或 UI 完成等价构造）；不是把所有用例前置提前造完。核心业务验证仍以正式 UI 步骤为主。

## 六、使用流程（新项目）

1. 读「项目背景.md」，提取：业务实体 / 造数端点 / 鉴权 / 账号 / 数据基线
2. 按统一接口生成项目造数器到 `runtime/factory/`（可参考 examples/）
3. 环境门禁验证：至少确认一种前置构造路径可用
4. 用例前置自造态写业务状态；构造策略放入 `data_setup`，执行框架 setupData 自动调度
5. 造数结果回填 produced + 通道匹配证据（UI 截图 manifest 或 API 请求/响应 evidence_refs）
