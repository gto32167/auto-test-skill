# 发布检查单

> 适用于对 `ai-qa-prd-workflow` **方案本身**的任何变更：门禁脚本逻辑、出厂模板、SKILL.md 原则、references 规则文本。项目执行产物（项目目录内的 YAML/Excel/报告）不适用本检查单。

## 四步硬要求

任何一步未完成，变更不算发布：

### 1. 同步出厂模板

门禁新增或收紧字段时，受影响的出厂模板必须同步到合规形状，否则新项目复制模板后会在第一道门禁被卡：

- 用例三件套：`assets/templates/requirements.yaml`、`coverage-matrix.yaml`、`test-cases.yaml`
- 执行两件套：`assets/templates/browser-execution-plan.yaml`、`test-execution-results.yaml`
- 数据工厂约定受影响时同步 `assets/data-factory/`；XLSX 列结构受影响时同步 `assets/templates/gen_xlsx_backfill.py`。

### 2. 全量自测通过

```powershell
Set-Location <技能目录>
$env:PYTHONDONTWRITEBYTECODE = "1"
python -m pytest references/scripts -q
```

存在失败即不得发布。新增脚本必须自带 `test_*.py` 并加入上面命令。

### 3. 出厂模板冒烟门禁

```powershell
Set-Location <技能目录>
py references/scripts/validate_case_design.py --requirements assets/templates/requirements.yaml --test-points assets/templates/coverage-matrix.yaml --final-cases assets/templates/test-cases.yaml --output "$env:TEMP\case_gate_smoke.json"
```

预期 `status: pass` 且 `quality_contract.enforced = true`；P0/P1/P2 风险比例可有明确告警。模板确认信息仅为示例，项目启动必须实际确认。

### 4. 补变更日志

在 `docs/history/CHANGELOG_年月.md` 增加「背景 / 变更 / 为什么这样改 / 验证」条目。**没有日志条目的变更视为未发布**——变更日志是追溯门禁演化与模板版本对应关系的唯一依据。
