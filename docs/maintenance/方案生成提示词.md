# 方案维护与再生成要求

> 本文件用于维护或重建 `ai-qa-prd-workflow`，不属于项目执行时需要读取的规则。

## 目标

生成或维护一套 PRD 驱动的 AI 测试工作流，覆盖需求拆解、用例设计、评审、执行、证据、回填和 Word 正式报告，并通过确定性脚本约束关键质量门禁。

## 必需结构

```text
SKILL.md
references/                 # 按阶段拆分的规范
references/scripts/         # 门禁、生成、回填和报告脚本
assets/templates/           # 交付模板和启动提示词
assets/data-factory/        # 通用数据构造约定
builtin_framework/          # pytest + Playwright 默认执行器
方案落地说明.md
从0开始使用说明.md
运行提示词.md               # 只链接唯一启动模板
```

历史记录、维护材料和汇报文件放在 `docs/`，不得作为 `SKILL.md` 的正常执行路由。

## 文档职责

- `SKILL.md`：触发范围、关键不变量和阶段路由。
- `overview.md`：阶段和模式路由。
- `case-design.md`：用例字段、覆盖、独立性和优先级。
- `review-standard.md`：评审评分、抽样和一票否决。
- `semantic-contract-gates.md`：语义契约和 observation 求值。
- `browser-execution.md`：执行、重试、三态、证据和回填事实。
- `delivery-gates.md`：唯一产物链、命令和停止条件。
- `execution-playbook.md`：登录、选择器、弹窗和其他操作经验。
- `framework-integration.md`：运行副本和框架绑定。

同一硬规则只能有一个完整定义。其他文档可以写摘要和链接，不得复制参数、表格或长段落。

## 核心验收

1. `06_final_test_cases.yaml` 是唯一最终执行源。
2. 用例设计、执行计划、执行结果和交付四道门禁均有确定性脚本。
3. P0/P1/P2 判级理由、组合比例、稳定执行顺序和 P0 全失败停止规则可机器校验。
4. 每个执行 attempt 保存语义哈希、轨迹、结构化观察值、业务数据和证据。
5. passed/failed 由 hard observations 求值，证据不足为 blocked。
6. 回填版实际结果保存可定位业务事实。
7. UI 证据校验真实文件、SHA-256 和语义 manifest；API 使用独立证据引用。
8. 正式交付包含模板版 Excel、回填版 Excel、Markdown 审计源和 Word 报告。
9. Allure HTML 可选，缺少命令不能阻断核心工作流。
10. 项目数据和登录态不得进入方案目录。
